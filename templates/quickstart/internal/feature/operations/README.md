# Operator features

Mount with `operations.New(deps).Register(groups)` and append `operations.Models()` to host models. Existing `/api/v1` auth groups supply the identity; this module independently requires the admin role for every operator route. Admin emails remain deployment configuration. Public settings never expose login, payment, mail or storage credentials.

## API

All JSON uses `{code, msg, data}`. List endpoints return `{items, total, page, limit}`; pages start at 1, default limit 20, maximum 100. `query` searches only documented identifiers and email/name fields as literal text, with a 200-character limit.

- `GET /admin/access`: lightweight administrator authorization check. Does not wait for reporting scans or require a database query.
- `GET /billing/credit-checkouts/:id`: authenticated, read-only confirmation for a credit Checkout Session owned by the caller. Returns `{state,credits_granted}`; states are `pending`, `processing` (paid, no matching grant yet), `fulfilled`, `failed`, or `expired`. Success requires the session's immutable grant (legacy event-ID grants remain recognized). An unrelated bonus, a processed event, or a later spent balance cannot imply or reverse fulfillment. Unknown, other-user, and non-credit sessions return 404. This endpoint never replays or grants credits.
- `POST /billing/credit-checkouts/:id/confirmation`: explicit authenticated payment-return fulfillment, with `Idempotency-Key` (up to 255 characters). Checks local ownership before contacting Stripe, then verifies provider ownership, paid/complete state, configured credits SKU and actual quantity. Uses the checkout session as the business idempotency key shared with webhooks and recovery. Already fulfilled purchases return their original result without another provider call. It creates no charge, subscription or refund; balance, ledger, lots and audit commit together. Deploy the backend before the frontend.
- `GET /admin/overview?days=7|30&timezone=Asia/Shanghai|UTC&mode=live|test`: preserves cumulative counts and adds `today_registrations`, `today_referrals`, `today_payments`, `paid_users`, `series`, `timezone`, `mode`, `as_of`. Defaults: 30 days, UTC+8, live payments. Series contains calendar date, registrations, attributed invitations, successful positive payments and first-time paying users; empty dates are zero-filled. Payment counts share the deduplicated invoice/checkout projection; zero/unknown amounts, unpaid checkout and unknown environments are excluded. Paid users are distinct current accounts with any historical positive payment in the selected environment (including credits); refunds do not erase historical conversion. This is neither DAU nor visitor conversion. Disabled modules return zero counts.
- `GET /admin/users`: profiles, effective `plan` / `membership` and current effective credit balances. Legacy balances retain their existing value until the explicit credit ledger migration.
- `GET /admin/users/:id/access`: fresh user identity/balance, the provider subscription snapshot, effective membership, payment-derived access and the current manual override.
- `PATCH /admin/users/:id/membership`: `{plan,expires_at?,reason}` plus `Idempotency-Key`. Plans: `automatic` removes the manual override; `free`, `starter`, `pro`, `premium`, `lifetime` set site access. Timed tiers require a future expiry; Lifetime has no expiry. Expiry restores payment-derived access. Writes are atomic with before/after audit and never alter authorization roles or provider subscriptions/charges. `membership.Models()` must be AutoMigrated alongside host models.
- `POST /admin/users/:id/credit-deductions`: positive integer `{amount,reason}` plus `Idempotency-Key`. Uses the shared credit service; balance, lots, actor and audit commit atomically. Insufficient balance returns 409 / `CREDITS_INSUFFICIENT_BALANCE`; retries cannot double-deduct. Grants continue using `/admin/credits/grants`.
- `GET /admin/subscriptions`: stored provider subscription snapshots, without raw provider data.
- `GET /admin/orders`: created checkout snapshots merged with persisted verified payment events. Provider/session references correlate checkout and invoice events into one record; repeated session reuse does not create another order. `amount_due` is the known order total; `amount` is the nullable actual payment, both in minor units. Additional fields include `checkout_session_id`, `plan`, `billing_interval`, `quantity`, `paid_at`, and `expires_at`; `created_at` is the original checkout creation time when known. `livemode` indicates real/test provider records where present. Subscription lifecycle events are excluded. Source records are scanned in bounded batches; for a large history, materialize this projection. Filters: exact `user_id`, `mode=live|test`, `status=paid|unpaid|expired|failed|unknown|no_payment_required`, inclusive `from` and exclusive `to` in RFC 3339. Expiry requires a persisted provider expiry event; local clocks never downgrade paid orders. The customer purchases endpoint always fixes the authenticated owner, ignores checkout intent snapshots, and retains verified payment-event behavior. Overview paid metrics also exclude intent.
- `GET /admin/referrals`: invitation records, optional exact referrer `user_id` and `status=pending|activated|expired`, referrer/referee emails, reward amount and deadline.
- `POST /admin/referrals/:id/retry-reward`: body `{reason}`, plus `Idempotency-Key`. Only an already activated record with a stored activation time can replay its original reward event. This does **not** qualify pending invitations or change rewards. A failed listener can be retried with the same key; the credit ledger prevents duplicate grants.
- `GET /admin/audit`: actor, reason, action, target, status and details for membership, credit, content, settings, reward reconciliation and failed authenticated administrator write attempts. Filter by `status=pending|succeeded|failed`; generic query matches action, target and actor. No audit deletion/update API is exposed.
- `GET /site/settings`, `GET /admin/settings`: `{brand_name, description, description_zh, headline_en, headline_zh, sender_email, sender_name, support_email, support_url, export_credit_cost, navigation, presentation_version:1}`. Defaults work before the first row is saved. Empty support fields mean support is not configured. `navigation` is `null` until an administrator saves menus (the frontend then uses its defaults), otherwise `{version:1, header:[{section,label:{en,zh},menu:"auto"|"manual"|"none",items:[article paths]}], footer:[{title:{en,zh},links:[sections]}]}`.
- `PATCH /admin/settings`: a subset of the writable settings (excluding `presentation_version`) plus a mandatory `reason`, and `Idempotency-Key`. Unknown fields are rejected. Export cost is an integer from 1 to 1,000,000. Support URLs must use HTTPS. Changes and before/after audit commit in one transaction. Sender identity is read on backend startup; sender credentials remain deployment-owned. Reusing a key with different data returns 409. Navigation accepts only the sections `home, features, use-cases, compare, docs, blog, resources, updates, pricing, examples, about, contact`: at most 6 unique header items, menus only on article directories, up to 10 unique article paths per manual menu (validated like content paths), and up to 4 titled footer groups of 8 links with no link repeated. Labels are at most 40 characters; an empty header label uses the default name. The settings body may be up to 32 KB.
- `POST /uploads/images`: authenticated multipart form with exactly one `file`. Maximum 5 MiB. Content is sniffed independently of supplied MIME/extension; PNG/JPEG/GIF headers are validated with a 40 megapixel limit, and WebP containers are checked. SVG is rejected. The response contains `id`, `url`, `content_type`, `size`, `filename`, `created_at`.
- `GET /uploads/images`: the signed-in user's metadata, paginated.
- `GET /uploads/images/:id`: image bytes for the same owner only. Use authenticated fetch and an object URL in the browser; this is not a public CDN URL. Files have generated names and private cache headers.

## Content and provider policy

- `GET /admin/articles`: paginated editable article library; `GET /admin/articles/:id` returns a revision, drafts and live snapshots.
- `POST /admin/articles`, `PUT /admin/articles/:id`: `{path,kind,position,version,translations,reason}` plus `Idempotency-Key`. Locales are `en`, `zh`, `ja`, `ko`, `es`, `fr` and `de` (`content.Locales`; the site interface covers `en` and `zh`); each translation has title, summary, Markdown body and optional SEO fields. Allowed paths: `/blog|docs|features|use-cases|compare/<lowercase-slug>`. Path/kind are immutable after creation. Draft and publication metadata are distinct.
- `POST /admin/articles/drafts`: `{kind,keyword,notes,locale}` asks the configured model (`host.ai`) for one article: `{path,translation,images:[{section,alt,description}]}`. Internal links are kept only to pages published in that locale; images the model writes are dropped, since article images come from uploads. Nothing is saved: the editor shows the draft and saves it through `POST /admin/articles`.
- `POST /admin/articles/translations`: `{from,to:[locales],translation}` returns `{translations:{locale:translation}}`. Image URLs must survive unchanged and links may only point where the source does; nothing is saved. Both writing endpoints return 503 / `AI_NOT_CONFIGURED` without a model, 502 / `AI_PROVIDER_FAILED` when the provider fails and 502 / `AI_OUTPUT_INVALID` when the reply is cut off or breaks these rules. They extend the response write deadline by the AI timeout per model request.
- `POST /admin/site-images`: one multipart `file` image (PNG, JPEG, GIF or WebP, up to 5 MB, identified by content) for articles. Returns `{id,url,width,height,content_type,size}`; `url` is `/api/v1/site/images/<id>` with `?w=&h=` when dimensions are known. `GET /site/images/:id` serves it publicly with `Cache-Control: public, max-age=31536000, immutable`, `nosniff` and a sandbox CSP.
- `POST /admin/articles/:id/publications`: `{version,locale,action:publish|unpublish,reason}` plus `Idempotency-Key`. Only the selected language changes. Conflicting versions return 409 / `CONTENT_VERSION_CONFLICT`.
- `GET /site/articles?locale=en|zh&kind=...`: paginated published summaries. `GET /site/articles/resolve?locale=...&path=...` returns `{article:null}` for absent/unpublished translations; drafts never leak.
- Public reads are database-only. Empty databases have no publications; source files never resurrect unpublished content.
- `page` content supports `/`, `/features`, `/use-cases`, `/compare`, `/resources`, `/docs`, `/blog`, `/about`, `/updates`. Other application and legal routes cannot be shadowed. Page SEO comes from the same published snapshot as its visible copy.
- `POST /admin/articles/import` with `{"apply":false}` previews the reviewed bilingual starter pack in `content/seed.json` without writing. `apply:true` requires an operation reason and `Idempotency-Key`; it inserts and publishes missing paths in one audited transaction. Existing paths, including drafts/unpublished entries, are skipped. The admin Content screen exposes both steps. Repeated imports cannot overwrite operator content. Import on the intended environment before switching the frontend to database-owned home/section pages.
- The starter pack is authored independently of frontend preview copy. `node scripts/sync-content-seed.cjs` validates it and never overwrites it. See `content/README.md` for evidence and maintenance boundaries.
- `GET /admin/integrations`: read-only configuration status; `PATCH /admin/integrations/:provider` returns 403 / `INTEGRATION_DEPLOYMENT_MANAGED`. No credential editing is supported. Old persisted provider overrides are still read at startup for compatibility; migration to deployment secrets must be deliberate, not an automatic deletion/switch.

## Shared audit service

`internal/audit.Service` is injected through host dependencies. It is an application service, not a separate process. `operations_audit_events` retains retry reservations; `audit_outcome_events` appends unique operation/outcome records. Existing audit entries are preserved. The audit UI queries reservations with current outcome; immutable outcome rows preserve failed reward attempts even after retry success.

Membership, credit grant/deduction/refund, website and article changes record success inside their local transaction. The default credit repository adapter invokes the injected audit callback; products providing a custom credit service must supply the same policy. Provider webhooks retain their billing ledger and are not duplicated as administrator changes. Failed authenticated administrator writes are recorded with route/status and a generic reason, without bodies, queries or credentials. Upstream sign-in failures remain the authentication service's responsibility. Request context reaches the DB/logger; request/trace identifiers are supplied by logging infrastructure and are not manually added to audit JSON.

## Storage

Uploads are disabled until `host.uploads.enabled=true`. `provider=local` requires an explicit `directory`. Local development files use generated paths inside an owner directory with private permissions and filesystem-root confinement. Do not expose that directory as static web content. A local production deployment needs a persistent private volume, backups, and a single shared filesystem.

For multiple instances or ephemeral deployments, set `provider=s3`, `bucket`, `region`, and optionally `endpoint`, `use_path_style`, `access_key_id`, `secret_access_key`. R2 uses region `auto` and its account S3 endpoint. Credentials belong in deployment secrets, never in settings. AWS may use its default credential chain when explicit credentials are omitted. Use a private bucket and disable public access. The same authenticated read route proxies private S3/R2 objects.

Provider changes do not migrate existing objects. Metadata records the original provider and returns unavailable if it no longer matches configuration. Move files and metadata through an explicit migration before switching a deployed storage backend.

The supplied SQL migration creates only these host feature tables. No migration or external database command is run by tests; tests use isolated SQLite databases and temporary directories. The existing quickstart startup migration wiring also includes these models after the host registers them.

Reporting currently streams bounded batches of users/referrals/payment events. It is intended for the starter’s operational volume; materialize a payment/reporting projection for larger histories. Calendar boundaries are evaluated in the requested timezone; response timestamps remain UTC. New membership overrides live in the additive `membership_overrides` table (AutoMigrate); rolling back the feature should leave that table intact.

`checkout_history` is an additive host-owned model registered by `operations.Models()`. The composition root attaches the optional billing checkout observer before serving requests. It stores only an allowlisted session/product/amount/time snapshot, never checkout/return URLs, credentials or raw metadata. Recording is best effort: failure is logged without withholding an already-created payment URL. History starts when this code is deployed and its model is migrated through normal startup; previously unrecorded abandoned sessions cannot be reconstructed. This analytics history is not a financial audit log or entitlement source.
