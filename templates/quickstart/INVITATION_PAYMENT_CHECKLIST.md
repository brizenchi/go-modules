# 邀请与支付操作检查手册

更新日期：2026-10-13。适用对象：不熟悉项目的测试同事。

按顺序操作，每项记录截图、时间和结果。本文是验收步骤，不代表已经完成浏览器实测。

## 1. 测试前准备

由开发提供已接好支付回调的正常 quickstart 测试网站、测试账号，以及每个积分包的积分数。
第一轮关闭免费试用，确保可以直接验证付款。不要用关闭支付、未装配奖励回调的 cmd/preview。
仅使用 Stripe Sandbox / 测试模式，不使用真实银行卡。

| 账号 | 用途 |
| --- | --- |
| A | 邀请人 |
| B | 从 A 邀请链接注册的新用户，测试会员变更 |
| C | 不通过邀请注册，测试普通购买及积分包 |
| D | 不通过邀请注册，测试终身会员 |
| E（补充） | 受邀注册但不买会员，测试买积分包不触发付费奖励 |

用不同浏览器或无痕窗口隔离账号。C、D 使用没有保存邀请码的全新浏览器环境。

| 页面 | 用途 |
| --- | --- |
| 网站地址 + `/referrals` | 复制邀请链接，查看邀请进度 |
| 网站地址 + `/billing` | 购买、会员、套餐变更、账单 |
| 网站地址 + `/credits` | 积分余额、收支明细 |

每步先记余额。普通注册赠送积分另算，不能把新用户总余额固定当成 10。

## 2. Stripe 测试信用卡

在本站点击购买后进入 Stripe 支付表单，选择银行卡付款，填写以下测试信息。

| 场景 | 卡号 |
| --- | --- |
| 正常成功付款 | `4242 4242 4242 4242` |
| 普通拒付 | `4000 0000 0000 0002` |
| 余额不足 | `4000 0000 0000 9995` |
| 交互付款需要 3D Secure 验证 | `4000 0025 0000 3155` |
| 先绑定客户、后续扣款失败（开发协助） | `4000 0000 0000 0341` |

有效期填未来日期，例如 `12/34`；CVC 填 `123`；姓名可填 `Test User`。
如要求邮编、地址，填写符合所选国家格式的测试信息。
3D Secure 卡用于本站发起的支付验证；保存为后续付款方式后，离线付款不一定再次要求验证。
普通拒付卡不适合先绑定再扣款的场景，续费失败请开发使用“先绑定后拒付”卡准备。

资料已核对 [Stripe 官方测试卡说明](https://docs.stripe.com/testing)。

## 3. 先确认当前奖励规则

| 阶段 | A 邀请人 | B 被邀请人 |
| --- | --- | --- |
| 有效邀请注册成功，不购买任何商品 | +20 | +10 |
| 首次符合条件的付费激活 | 再 +20 | 再 +10 |
| 重复登录、后续续费、升级 | 不再次发放 | 不再次发放 |

两阶段完成后，邀请带来的累计增量为 A +40、B +20。购买 Pro 本身没有额外套餐赠送积分。
付费奖励目前开启，是可由开发关闭的独立逻辑；关闭后应按修改后的规则验收。

## 4. 邀请注册

### INV-01：不买会员也获得奖励

1. A 登录 `/credits`，记录余额 A0。
2. A 打开 `/referrals`，复制邀请链接。
3. 无痕窗口打开链接，B 使用从未注册过的新邮箱完成注册。
4. B 不购买任何商品。
5. 双方打开 `/credits`，点击“刷新”。

- [ ] A 余额为 A0 +20，明细出现“邀请注册奖励 +20”。
- [ ] B 明细出现“受邀注册奖励 +10”；普通注册赠送是另一笔。
- [ ] A 的邀请列表出现 B，可显示“待订阅激活”。此状态不影响注册奖励到账。

### INV-02：重复登录不能再奖励

1. 双方刷新多次，退出并重新登录。
2. B 再打开 A 的链接并登录。

- [ ] 注册奖励各只有一笔，余额不因上述动作增加。
- [ ] 邀请列表没有重复的 B。

### INV-03：没有邀请及老用户登录

1. C 不使用邀请链接，在全新浏览器环境直接注册。
2. C 查看 `/credits`。
3. C 再打开 A 的邀请链接并登录。

- [ ] C 可以有普通注册赠送，但没有受邀注册奖励。
- [ ] 老账号 C 不新增邀请绑定，A 不增加邀请奖励。

补充：用无效邀请码注册，不应给任何邀请人发奖；A 打开自己的链接登录，不应获得自邀奖励。

## 5. 购买 Pro 及付费邀请奖励

### PAY-01：付款前退出

1. 记录 A、B 当前余额。
2. B 打开 `/billing` →“选择套餐”→“专业版”→“按月”→“前往支付”。
3. 不提交付款，退出支付页，再返回本站刷新。

- [ ] 未开通付费 Pro；没有新增付费邀请奖励。
- [ ] 注册奖励保留，不被扣回。

### PAY-02：Pro 月付成功

1. B 再次选择专业版、按月，点击“前往支付”。
2. 核对商品和金额，用成功卡付款。
3. 返回 `/billing`，在“当前订阅”点击“刷新账单”。
4. 在“购买记录与会员权益”点击该区域的“刷新”。两个刷新按钮各更新对应内容。

- [ ] 当前套餐“专业版”、状态“生效中”、周期“按月”，有周期结束日期。
- [ ] “周期结束后终止”为“否”。
- [ ] 实际会员为 `pro · 有效`。
- [ ] 购买记录最终显示“已付款 / 已处理”。
- [ ] “账单记录”有对应账单，“查看”可以打开收据。

双方再打开 `/credits` 刷新：

- [ ] A 相对付款前再 +20，明细“邀请付费奖励”。
- [ ] B 相对付款前再 +10，明细“受邀付费奖励”。
- [ ] A 的邀请记录已激活，“付费激活奖励”统计增加 20（不包含注册奖励）。

### PAY-03：持久化及账号隔离

1. B 退出重新登录，查看会员和积分。
2. 切换 A、C 登录，查看各自页面。

- [ ] B 仍有 Pro 和原购买记录，没有重复加分。
- [ ] A、C 看不到 B 的购买记录和私人积分明细。
- [ ] 普通用户不能访问管理员页面。

模板没有自动出现的 Pro 专属功能页面。若产品已接入付费功能，由开发提供具体入口：
B 达到等级要求时可用，免费或等级不足账号不可用。

## 6. 升级、降级和跨周期变更

### SUB-01：Pro 月付升级 Premium 月付

1. B 选择“高级版”“按月”。
2. 记录预览中的“变更方式”“当前应付”。
3. 点击“变更套餐”；如需补付款，点击“完成付款”。
4. 刷新订阅与实际会员。

- [ ] 付款成功后为高级版、`premium · 有效`。
- [ ] 如等待付款，保持原 Pro，不提前升级。
- [ ] 实际扣费与预览核对，无意外重复扣费。
- [ ] 双方不再次获得付费邀请奖励。

### SUB-02：降级并撤销预约

1. B 选择“入门版”“按月”，预览应显示下个计费周期生效。
2. 点击“变更套餐”。

- [ ] 当前仍高级版，出现待生效入门版及日期。
- [ ] 尝试再次变更或退订，应阻止或提示先处理已有变更。

3. 点击“撤销待生效变更”。

- [ ] 预约消失，仍是高级版。

### SUB-03：月付、年付组合

用独立账号测试，或先清除原有预约，避免多个场景相互干扰。

| 操作 | 预期 |
| --- | --- |
| 同档月付 → 年付 | 立即切换，重新开始周期，核对费用与日期 |
| 年付 → 月付 | 下周期切换 |
| 高档月付 → 低档年付 | 降档，下周期生效 |

首次购买也要覆盖三档 × 月/年共六种组合。每种使用独立账号：核对购买套餐、金额、有效期、购买记录。
不要把一个账号已经成功买 Pro 当作其他价格配置也通过。

## 7. 取消、恢复、到期及续费

### SUB-04：取消续费

1. 确认已撤销待生效变更。
2. B 在“当前订阅”点击“周期结束时取消”，刷新。

- [ ] “周期结束后终止”为“是”，显示权益终止时间。
- [ ] 本期未结束，会员仍有效。
- [ ] 不自动退款，不清空积分。

### SUB-05：恢复订阅

1. 到期前点击“恢复订阅”，刷新。

- [ ] 终止标记恢复为“否”，取消安排消失，原会员有效。
- [ ] 不重复奖励。

### SUB-06：时间推进（开发协助）

开发准备模拟时钟且关联本站测试账号；测试同事检查页面。
不能修改电脑日期来模拟。Stripe 时钟不改变本站服务器时间，到期权限还需开发校验应用时间边界。

| 场景 | 预期 |
| --- | --- |
| 预约降级到下一周期 | 套餐变为预约低档，旧预约清除 |
| 已取消续费，到期 | 实际会员失效；旧订阅结束，需要重新购买 |
| 正常续费成功 | 有效期延后，新增续费账单，会员有效 |
| 续费失败进入欠费状态 | 有付款异常；基础版无欠费宽限期 |
| 后续续费 | 不再发邀请奖励 |

检查“实际生效会员”，不能只凭旧套餐名称判断是否有权限。

## 8. 积分包

### CR-01：购买及重复刷新

1. C 记录余额 X，开发告知每包 Q 积分。
2. `/billing` →“购买积分”→数量 2 →“购买积分包”→成功付款。
3. 点击“积分余额与明细”，在 `/credits` 点击“刷新”。

- [ ] 余额 X +2×Q，明细有购买积分，购买记录有对应订单。
- [ ] 会员等级不变，重新登录不重复加分。

### CR-02：数量与退出

- [ ] 填 0、负数、小数、101，不能正常提交购买，有校验提示。
- [ ] 付款前退出，不增加积分。
- [ ] 若 Stripe 页面允许调整数量，按实际支付包数到账。

### CR-03：受邀用户只买积分包

1. E 通过 A 邀请注册，先确认注册奖励已到账。
2. E 不买会员，只购买积分包。

- [ ] E 仅增加实际购买积分；A 没有新增付费邀请奖励。
- [ ] E 的邀请仍未因这次积分购买变成付费激活。

## 9. 终身会员

### LIFE-01：购买和限制

1. D 不通过邀请注册，确认没有有效周期订阅。
2. `/billing` →“终身版”→“购买终身版”→成功付款。
3. 刷新两个区域。

- [ ] 当前终身版，实际会员 `lifetime · 有效`，没有正常到期日。
- [ ] 无额外套餐赠送积分，不需要周期续费。
- [ ] 再买会员被阻止；仍能正常买积分包。
- [ ] B 仍有有效周期订阅时买终身版被阻止；只关闭续费还不够，需等原订阅结束。

补充：使用新受邀账号测试终身购买，符合付费激活条件时，应只发一次对应付费邀请奖励。

## 10. 失败、认证及回调异常

### ERR-01：拒付及余额不足

1. 独立账号分别使用普通拒付卡、余额不足卡发起首次购买。
2. 返回本站刷新。

- [ ] 支付失败，不开通付费会员、不发购买积分或付费邀请奖励。
- [ ] 已经到账的注册奖励保留。
- [ ] 换成功卡完成支付后，只发一次该次购买权益。

### ERR-02：3D Secure 验证

1. 从本站发起购买，使用 3D Secure 测试卡。
2. 第一轮在模拟验证页面失败或取消，检查没有提前发权益。
3. 第二轮重新支付，完成模拟验证，检查最终正确到账。

### ERR-03：升级扣款失败（开发协助）

开发为有订阅的测试客户设置先绑定后拒付的付款方式，再测试升级。

- [ ] 升级失败或待付款时保留旧套餐。
- [ ] 换成功付款方式并完成补付款后，才切换新套餐。
- [ ] 补付款不会再次发放已发过的付费邀请奖励。

### ERR-04：关闭页面、重复和漏发通知（开发协助）

| 操作 | 检查 |
| --- | --- |
| 实际付款成功后关闭页面，不回本站 | 重新登录仍能查询到订单及权益 |
| 重发同一个支付事件 | 不重复加积分、不重复发邀请奖励 |
| 暂停支付通知，保持补偿任务运行 | 后续补偿正确到账，数量不重复 |
| 注册或付费的第二笔奖励暂时失败，再重试 | 已成功的一方不再加，只补齐失败的一方 |
| 多次快速点击购买 | 不产生多份冲突的有效会员订阅 |

免费试用另开测试场景：注册邀请奖励正常发，试用开始不发额外付费邀请奖励，符合条件的转付费后才发。
退款后自动扣回积分或撤销会员尚未实现，不按自动撤回验收。

## 数据库检查（可交开发核对）

先按邮箱在 users 表找到 id，其他表按 user_id 查询，不修改数据。

| 场景 | 数据变化 |
| --- | --- |
| 邀请注册 | referrals 新增双方关系；users.credits 分别 +20/+10；user_credit_transactions 新增两笔来源 referral_signup_inviter / referral_signup_invitee |
| 首次付费邀请奖励 | referrals.status=activated，reward_credits=20（仅付费阶段邀请人）；两笔流水来源 referral_inviter / referral_invitee，双方再次 +20/+10 |
| Pro 月付 | billing_subscriptions.plan=pro、status=active、billing_interval=monthly，period_end 有值；users.role 不变 |
| 取消续费 | cancel_at_period_end=true，cancel_effective_at 有值，plan 保留当前套餐 |
| 积分包 | users.credits 增加实际购买量，user_credit_transactions 增加 source=stripe 的流水 |
| 终身会员 | plan=lifetime、status=active、product_type=lifetime，period_end 为空 |

付款还会产生 billing_events，多条事件正常；最终 processed=true。页面“支付成功”不等于已经发放完毕。
两阶段的奖励流水以来源和邀请 ID 去重，每阶段每人最多一笔。
退款自动扣回积分或撤销会员尚未实现，不能按自动撤回验收。

每项填写：账号 / 操作时间 / 操作前余额 / 操作后余额 / 截图 / 通过或失败。
