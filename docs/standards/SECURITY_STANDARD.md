# 安全规范

发现安全漏洞时如何上报，见 [SECURITY.md](../../SECURITY.md)。

## 输入校验

- 所有外部输入都不可信：请求体、查询参数、请求头、Webhook、第三方 API 返回的数据；
- 在 handler 层校验格式、长度、取值范围：使用 `ShouldBindJSON` 加结构体校验，或者显式检查；
- 字符串设置最大长度；数字检查范围；枚举值检查是否在白名单内；
- 校验失败返回 400，不把内部的解析错误原样返回给客户端。

## 鉴权与越权

- 需要登录的接口挂在 `User` 分组下，后台接口挂在 `Admin` 分组下。**禁止**在 handler 里自己解析 token；
- **每次访问资源都要检查归属**：根据 ID 查询时带上 `user_id` 条件（`WHERE id = ? AND user_id = ?`），不能只依赖前端隐藏入口；
- 访问别人的资源时返回 404，不返回 403，避免暴露资源是否存在；
- 权限判断在服务端完成，前端的判断只用于界面展示；
- 管理员的敏感操作（修改配置、补发或退回积分）必须写审计日志。

## 认证

- JWT 密钥和 OAuth state 密钥要分开生成，长度至少 32 字节；
- 密码使用 bcrypt 存储（见管理员密码登录的实现）；登录失败不区分"用户不存在"和"密码错误"；
- 登录、验证码这类接口有频率限制和失败次数上限；
- 退出登录时吊销 token（`auth_token_revocations`）。

## 注入类问题

| 类型 | 规则 |
| --- | --- |
| SQL 注入 | 只使用参数化查询，禁止拼接 SQL；动态的排序字段使用白名单 |
| XSS | 前端默认依赖 React 的转义；禁止使用 `dangerouslySetInnerHTML` 渲染用户输入；邮件模板里的用户输入要做 HTML 转义 |
| 命令注入 | 不执行由用户输入拼接出来的系统命令 |
| 路径穿越 | 文件路径不直接使用用户输入；上传的文件用生成的 ID 命名 |
| **SSRF** | 服务端发起的 HTTP 请求只能访问配置好的第三方域名；**禁止**请求用户提交的任意 URL。如果确实需要（比如抓取网页预览），必须校验协议、拒绝内网地址，并设置超时 |
| 开放重定向 | 登录、支付完成后的跳转地址必须在前端域名的白名单内（见 `billingapp.NewOriginReturnURLValidator`） |

## Webhook

- **先验签，再处理**（Stripe 使用 webhook secret）；验签失败返回 400；
- 按事件 ID 做幂等处理，同一个事件重复送达只处理一次；
- 不信任 Webhook 里的金额、用户 ID：以向第三方查询到的结果为准，或者和自己数据库里的记录比对。

## 密钥管理

| 规则 | 说明 |
| --- | --- |
| 存放位置 | 只放在部署平台的环境变量（Dokploy、Railway）或本地 `.env` 文件中；`.env` 已经加入 `.gitignore` |
| 禁止 | 提交到 git、写进代码或镜像、打印到日志、发到聊天工具里 |
| 测试数据 | 使用明显是假的值：`sk_test_not-a-real-key`、`whsec_not-a-real-secret`。避免触发密钥扫描 |
| 权限最小化 | 第三方 token 只申请需要的权限（比如 Grafana 只给 `traces:write`、`metrics:write`、`logs:write`） |
| 隔离 | 不同环境（dev / prod）、不同公司使用不同的密钥 |
| 轮换 | 人员离开、怀疑泄露、或者每年一次，轮换生产环境的密钥 |
| 扫描 | 提交前的 `gitleaks` 钩子和 CI 都会扫描（见 [CI_QUALITY.md](./CI_QUALITY.md)） |

### 密钥泄露处理
1. **立即在服务商后台作废这个密钥**，生成新密钥并更新部署环境。这一步最重要，改写 git 历史并不能撤回已经泄露的密钥；
2. 检查服务商的使用记录，确认泄露期间有没有异常调用；
3. 如果密钥还没有推送到远程，在本地改写历史删除它；已经推送的，按 GitHub 的说明处理，并认定它已经泄露；
4. 按 [INCIDENT_RESPONSE.md](./INCIDENT_RESPONSE.md) 记录并复盘。

## 日志与隐私

- 不记录密码、token、完整的银行卡号、验证码、Authorization 头。`foundation/slog` 默认会把常见的敏感字段替换成 `[REDACTED]`，项目特有的字段加到 `log.redact_keys`；
- SQL 日志默认不带参数值；访问日志不记录 query string；
- 邮箱等个人信息只在排查问题必需时记录；不记录请求体和响应体的全文。

## HTTP 安全

- 安全响应头由 `ginx.Secure`、`ginx.NoCache` 设置；HSTS 在入口层（Traefik）统一配置；
- Cookie 设置 `Secure`、`HttpOnly`、`SameSite`；
- CORS 只允许白名单内的域名，不使用 `*`；
- 文件上传：限制大小和类型，校验文件内容而不只是扩展名，保存在对象存储里，不放在应用目录下。

## 依赖安全

- CI 运行 `govulncheck` 和 `npm audit`；出现高危漏洞时优先修复；
- Dependabot 每周提交依赖升级的 PR（见 [CI_QUALITY.md](./CI_QUALITY.md#依赖管理)）；
- 引入新依赖前确认：维护是否活跃、许可证是否允许商用、是否有已知漏洞。
