upgraded with `keel update` (local edits are kept); conventions specific to this

## Managing keel

```bash
keel status               # version, components, hooks, GitHub settings
keel config               # choose components again, change answers
keel update               # move to a newer release, keeping local edits
keel github --dry-run     # preview GitHub settings; drop --dry-run to apply squash merges, rulesets, secret scanning
```

## Changing the standards

- Shared standards: change and release them in keel, then run `keel update` in each project.
- This project's conventions: edit [PROJECT.md](./PROJECT.md) and the project section of `AGENTS.md`.
- New rules that a tool can check belong in CI; only checks that must stop a commit
  before it leaves the machine belong in the Git hooks.
